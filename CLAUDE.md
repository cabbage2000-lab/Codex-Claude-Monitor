# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a local VS Code extension, not intended for marketplace publishing. It shows token/context usage percentages for the current Codex or Claude Code session in the status bar. The project is plain CommonJS with no build step and no dependencies beyond Node built-ins and the `vscode` API.

## Commands

```bash
# Run all tests with Node's built-in test runner. No npm install is required.
npm test

# Run one test file.
node --test test/claudeUsage.test.js

# Package the extension into dist/*.vsix (fetches @vscode/vsce via npx).
npm run package
```

For local installation, symlink the project directory to `~/.vscode/extensions/codex-claude-monitor`, then run `Developer: Reload Window` in VS Code. See `README.md`.

## Architecture

Data flow: local session JSONL files -> provider parsers with workspace filtering -> latest active provider selection -> status bar.

Workspace filtering: `readLatestAgentUsage` accepts optional `workspaceFolders` as absolute paths. Only sessions whose cwd is inside a workspace folder, including subdirectories, are counted. Empty arrays disable filtering. Claude is filtered by munged directory names, where non-alphanumeric characters are replaced with `-` and prefix matching supports subdirectories, so files do not need to be opened. Codex candidates are sorted by descending mtime, then each first line is read until `session_meta.payload.cwd` matches. See `docs/specs/2026-06-03-workspace-filter-design.md`.

- `src/sessionFiles.js`: shared provider utility layer for recursive scanning with `walkFiles`, descending mtime sorting, `parseJsonLine`, `calculateContextPercent`, and `readLastMatchingEvent`, which parses JSONL line by line, returns the last matched entry, and caches by mtime plus size.
- `src/codexUsage.js`: recursively scans `~/.codex/sessions` for `rollout-*.jsonl`, picks the newest file by mtime, and reads the last `token_count` event. Percentage = `last_token_usage.input_tokens / model_context_window`.
- `src/claudeUsage.js`: recursively scans `~/.claude/projects` for `.jsonl`, picks the newest file, and reads the last `type: "assistant"` entry with `message.usage`. Context tokens = `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`; the context window is inferred from the model name by `inferClaudeContextWindow`: model names containing `1m` or `fable`, or `claude-opus-4-7` / `claude-opus-4-8`, use 1M, otherwise 200k; when the observed context tokens exceed the inferred window (unlisted big-window models like Sonnet 5), it upgrades to 1M so the percent never exceeds 100. File selection skips files without an assistant usage entry (freshly started sessions, non-interactive `claude -p` sessions), trying the newest 10 by mtime.
- `src/claudeStatuslineUsage.js`: reads Claude subscription rate limits from the statusline usage cache file (`~/.claude/.usage-cache.json`, name in `CACHE_FILE_NAME`) written by `scripts/usage-cache.sh`. Claude Code passes a JSON blob on stdin to the configured statusline command; for subscribers it includes a `rate_limits` block with the 5-hour and 7-day windows. That block comes from the **HTTP response headers** of ordinary API calls (`anthropic-ratelimit-unified-{5h,7d}-utilization` / `-reset`), which the CLI keeps only in process memory — hence "absent until the first API response of a session". The CLI scales the header's 0–1 `utilization` by 100 into `used_percentage`, and drops the `seven_day_opus` / `seven_day_sonnet` / `overage` windows it also parses, so the statusline can never expose more than these two. `readClaudeStatuslineUsage(claudeRoot)` maps `five_hour` → `primary` (`window_minutes` 300) and `seven_day` → `secondary` (10080), converting `used_percentage` → `used_percent` and passing `resets_at` (Unix seconds) through, and returns `{ rateLimits, capturedAt }` or `null`. A present-but-malformed window (non-numeric `used_percentage`) invalidates the whole read; a missing window is simply omitted. Results are cached by (mtime, size) like `readLastMatchingEvent`. **This source only works in terminal sessions**: the statusline input builder is called from an ink `useCallback`, i.e. it is part of the TUI render path, so a Claude Code session driven purely through the VS Code panel never runs it and this cache goes stale — that gap is what `src/claudeOAuthUsage.js` covers. This replaced the removed `claudeRateLimits.js`, which parsed `claude -p "/usage"` text output — that command no longer emits subscription limits (its `-p` output is now a usage-behavior report from a local transcript scan).
- `src/claudeOAuthUsage.js`: reads Claude subscription rate limits by calling `GET {ANTHROPIC_BASE_URL|https://api.anthropic.com}/api/oauth/usage` directly — the same call the official Claude Code VS Code extension makes for its usage panel. Unlike the statusline bridge this works in every mode, including panel-only usage. Credentials come from `~/.claude/.credentials.json` if present, else the macOS Keychain item `Claude Code-credentials` via `security find-generic-password`; `extractAccessToken` pulls **only** `claudeAiOauth.accessToken` and rejects an `expiresAt` in the past, with `toExpiryMs` disambiguating the timestamp by magnitude (`>= 1e12` is milliseconds, below it seconds) and also accepting an ISO string or a numeric string — the field has no stated contract and misreading milliseconds as seconds would mark every token expired, taking the source silently dark. A missing or unparseable expiry is treated as usable and left for the endpoint to judge. The refresh token is deliberately never read or used, because OAuth refresh tokens rotate and refreshing here could sign Claude Code out; an expired token simply yields no data until Claude Code refreshes it. Requests send `Authorization: Bearer`, `Content-Type`, and `anthropic-beta: oauth-2025-04-20` (CLI constant `G0`) with a 5s timeout on `node:https`. `mapUsageResponse` maps `five_hour` → `primary` / `seven_day` → `secondary`; note this payload's `utilization` is **already 0–100** (no scaling, unlike the response headers) and `resets_at` is an **ISO 8601 string** (converted to Unix seconds by `toUnixSeconds`, which also tolerates a raw number). `utilization: null` means the window does not apply and is omitted; a non-numeric one invalidates the read. `SCOPED_WINDOWS` additionally collects the model-scoped weekly windows (`seven_day_opus` / `seven_day_sonnet`) into `rateLimits.scoped`, each with an explicit `label` because they share the 7-day length with `seven_day` and could not otherwise be told apart; these are supplementary, so a malformed one is skipped rather than invalidating the read, and they are absent on any plan that does not meter Opus separately. The payload's remaining window keys (`tangelo`, `nimbus_quill`, `iguana_necktie`, …) are internal experiment codenames and are deliberately **not** surfaced — unlike cc-switch, which collects every unknown key. `refreshClaudeOAuthUsage` is async, throttled to `MIN_REFRESH_INTERVAL_MS` (5 min, matching Claude Code's own write throttle) with `FORCED_REFRESH_INTERVAL_MS` (30s) as the floor for an explicit user refresh, shares one in-flight promise, doubles a backoff up to 30 min on failure, and never throws — a failure keeps the previous snapshot. `readClaudeOAuthUsage` is the synchronous accessor the status bar path uses. **Proxy support is mandatory, not a convenience.** `node:https` ignores `http_proxy` / `https_proxy` entirely, and Anthropic answers a direct connection from some regions with `403 {"type":"forbidden","message":"Request not allowed"}` — byte-for-byte what an account-level refusal returns. `resolveProxyUrl(hostname, override, env)` picks the proxy (scheme-specific env var first, lowercase before uppercase, bare `host:port` tolerated like curl, `socks` rejected since CONNECT cannot speak it) and honours `no_proxy` (suffix match, optional leading dot, bare `*`); `connectViaProxy` opens a CONNECT tunnel that TLS then runs on top of, rejecting a non-200 so a proxy's 407 does not surface as an opaque TLS error. `extension.js` passes VS Code's own `http.proxy` setting as `proxy`, which outranks the environment — an editor launched from Finder or the Dock inherits no shell environment and would otherwise see no proxy at all. Because of that collision, **a 401/403 is never a permanent verdict**. It sets `state.usageRefused`, which enables the fallback quota probe and is surfaced by `isClaudeOAuthUsageUnsupported` for diagnostics, but the endpoint is retried on every subsequent attempt (under normal backoff) and any later success clears the flag. An earlier note here claimed the endpoint refuses `team` / `enterprise` subscriptions outright, "verified" by a 403 — that verification was made on a direct, unproxied connection and was wrong; the same account returns full `five_hour` / `seven_day` data once the request goes through the proxy. Only `probeUnsupported` is still sticky, and only for the one unambiguous case: a probe that succeeds but carries no rate-limit headers, which is a property of the plan rather than the network. `deps` in the options allows injecting `readAccessToken` / `requestUsage` / `requestQuotaProbe` for tests.
- `scripts/usage-cache.sh`: the statusline bridge. Reads the statusline stdin JSON, snapshots `.rate_limits` (via `jq`) plus a `capturedAt` Unix-seconds timestamp to `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.usage-cache.json` (atomic write: temp file + `mv`), then passes stdin through unchanged so an existing statusline command can pipe through it. Every failure (missing `jq`, absent `rate_limits`, unwritable dir) is swallowed so the status line still renders. Wire it into an existing statusline script by piping stdin through the helper in the background.
- `src/agentUsage.js`: aggregation layer. It reads both providers, selects the most recently active one by `updatedAt`, and formats status bar text and tooltip text. Status bar text is `{provider} $(comment) {percent}` plus compact rate-limit segments joined with ` · ` (e.g. `Codex $(comment) 3% · $(history) 45% · $(calendar) 23%`, `Claude $(comment) 50% · $(history) 25% · $(calendar) 8%`). Segments come from `formatRateLimitsStatusBar` using codicon icons: `$(history)` for hour-scale windows (e.g. 5h) and `$(calendar)` for multi-day windows (weekly / Nd); `$(comment)` (a speech bubble) marks the context percent in place of an emoji so it renders consistently across themes and needs no translation. Codex segments come from session JSONL `rate_limits`; Claude segments come from `options.claudeRateLimits` injected by `extension.js` (whichever of the OAuth read and the statusline cache is fresher), attached in `readLatestAgentUsage` only when Claude wins and never overwriting provider-supplied data, with `options.claudeRateLimitsCapturedAt` riding along as `usage.rateLimitsCapturedAt`. `pickFreshestRateLimitSnapshot(candidates)` does that selection: it drops empty candidates and those without `rateLimits`, then takes the highest `capturedAt`. The friendly Claude model name (with `(1M)` marker) and rate-limit reset times/countdowns are intentionally kept out of the status bar and surfaced only in the tooltip. `getUsageSeverity` maps context percent to `low` (<50%), `medium` (50–79%), or `high` (>=80%) for status bar coloring. Tooltip rows are ordered as context row, model row (friendly name with `(1M context)` marker), Claude token-composition rows from `formatClaudeTokenDetail` (input/cache-read/cache-create plus a cache-hit percent; empty for providers like Codex without this breakdown), then rate-limit rows. Rate-limit rows for both providers are formatted by `formatRateLimits` as `5h usage: 21% · Reset at 14:32 (in 2h 13m)`, taking `rateLimits.primary`, `rateLimits.secondary`, then any `rateLimits.scoped` entries, whose own `label` overrides the duration-inferred one; scoped rows are tooltip-only, since letting them into the status bar would grow the segment list without bound. the `(in …)` countdown comes from `formatTimeLeft` (total minutes rounded up, at most two units, zero minor unit omitted) and is dropped once `resets_at` is in the past, so stale sessions keep the absolute time only. When rate-limit rows are present and `usage.rateLimitsCapturedAt` is set, a final `Usage updated 2m ago (11:58)` row is appended by `formatUsageCaptureRow`; its relative part comes from `formatTimeAgo` (elapsed since a past timestamp, "just now" under a minute or for future/skewed times, at most one unit). Staleness: `isRateLimitSnapshotStale` compares `usage.rateLimitsCapturedAt` against `RATE_LIMITS_MAX_AGE_MS` (1 hour, matching Claude Code's own TTL for its persisted utilization cache); a stale snapshot is dropped from **both** the status bar segments and the tooltip rows, replaced by a single `Rate limits hidden — last snapshot 4h ago (stale)` row, on the principle that a wrong percentage is worse than none. That row appears only when the hidden data would actually have rendered rows. A snapshot with no `capturedAt` (Codex, whose limits come from live session JSONL) is never treated as stale.
- `src/extension.js`: VS Code entry point and the only file that depends on the `vscode` API. It owns the main status bar item (priority 90; click runs `agentTokenStatus.refresh`) and the refresh timer with default 10s interval. Rendering is split from fetching: `renderStatus()` paints from synchronously available data only, while `refreshStatus({force})` also calls `scheduleClaudeOAuthUsageRefresh` — a fire-and-forget background read that repaints via `renderStatus()` when it lands, so a slow or failing network never blocks the status bar and no recursion occurs. Clicking the status bar passes `force: true` so an explicit refresh actually re-reads the limits. `readUsage` combines both Claude rate-limit sources with `pickFreshestRateLimitSnapshot` — `readClaudeOAuthUsage()` (skipped entirely when `enableClaudeOAuthUsage` is false) and `readClaudeStatuslineUsage(claudeRoot)` — and forwards `claudeRateLimits` / `claudeRateLimitsCapturedAt` to `readLatestAgentUsage`. `deactivate` clears `statusItem` / `handoffItem` so an in-flight OAuth read's repaint becomes a no-op instead of touching disposed items. Configuration reads cover `agentTokenStatus.sessionsRoot`, `claudeRoot`, `refreshIntervalMs`, and `enableClaudeOAuthUsage`, plus the severity-to-theme-color mapping via `SEVERITY_COLORS` (`charts.green` / `charts.yellow` / `charts.red`). It also owns a second status bar item `handoffItem` (priority 89, `$(export) Handoff`) shown only when `contextPercent > HANDOFF_THRESHOLD` (50); clicking it runs `agentTokenStatus.handoff`, which composes a handoff prompt via `src/handoff.js`, writes it to the clipboard, and shows an information message. Surfacing the suffix is the only automatic behavior — generating and copying the prompt is strictly user-triggered. The latest `usage` is cached in `latestUsage` so the command does not need to re-read JSONL.
- `src/handoff.js`: pure logic layer for the handoff feature, decoupled from `vscode`. `buildHandoffPrompt(usage, gitInfo)` composes a compact, paste-ready continuation prompt: a one-line header noting the previous context percent, the session file path and git branch (omitted when missing), then a minimal four-line skeleton (`Task` / `Done` / `Next` / `Constraints`) whose placeholders are filled by the session's Claude after paste. Only facts the model cannot infer from the session are included; per-token breakdown and verbose promptify sections are intentionally omitted. `collectGitInfo(cwd)` runs `git` through `child_process` and returns `{ branch, status, recentCommits }` or `null` when `cwd` is not a repo (only `branch` is surfaced in the prompt).

Provider contract: every provider's `readLatestXxxUsage(root, workspaceFolders)` returns the unified shape `{ provider, sessionFile, updatedAt, contextTokens, contextWindow, contextPercent, ... }`. Codex uses file mtime for `updatedAt`; Claude uses message timestamp. To add a provider, implement this contract and append it to the candidates array in `agentUsage.js`. Formatting belongs only in the aggregation layer through `formatAgentUsage`, `formatCount`, and `formatRateLimits`.

Key design: parsing logic in `sessionFiles`, `codexUsage`, `claudeUsage`, and `agentUsage`, plus the handoff prompt builder in `handoff`, is fully decoupled from the `vscode` API, so it can be tested directly with Node's built-in test runner without a VS Code test environment. Tests use `test/testUtils.js` helpers such as `makeTempDir`, `writeJsonl`, and `setMtime` to create temporary JSONL fixtures for parser and selection behavior.

When adding support for a new model context window, update `inferClaudeContextWindow` in `claudeUsage.js`. When a new model *family* appears, also add it to the family alternation in `formatModelName` in `agentUsage.js` (currently `opus|sonnet|haiku|fable`), or the tooltip falls back to the raw model id. That function handles both id layouts — family-first (`claude-opus-5`, `claude-opus-5[1m]`, `claude-opus-4-8`, `claude-haiku-4-5-20251001`) and the legacy version-first form (`claude-3-5-sonnet-20241022`) — and matches versions as one or two digits followed by a non-digit so a trailing release date is never read as a version.
